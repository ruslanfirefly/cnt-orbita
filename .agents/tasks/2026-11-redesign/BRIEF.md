## 1. Контекст

Сайт СНТ «Орбита» (https://cnt-orbita.ru/) построен на Hugo 0.168.0 + тема Hugo Theme Stack.
У сайта появился **новый фирменный стиль**: логотип — тёмно-синий дом с трубой и дымком внутри
орбитальной эллиптической траектории со звездой и точкой-планетой, на ярко-бирюзовом фоне.
Новый бренд: **navy ink + cyan accent**. Текущая тема Stack визуально шаблонная, серый текст
(#707070) не проходит проверку контраста (Lighthouse Accessibility 0.94), меню из 12 пунктов
без приоритизации, категории захламлены дублями.

**Цель редизайна:** современный, понятный садоводам всех возрастов, корректный на любом
устройстве интерфейс в новом фирменном стиле, без потери функциональности (RSS, поиск,
тёмная тема, архивы).

**Жёсткое ограничение — обратная совместимость:** весь контент уже существует и
опубликован (статьи 2023–2026, категории, архивы, изображения). Редизайн не имеет права
ломать существующие URL (`/p/:slug/`), рендеринг старых постов, RSS и поиск — всё должно
работать ровно как раньше, только в новом оформлении.

Прототип уже содержит: sticky-шапку с SVG-плейсхолдером логотипа (строка ~305, `viewBox="0 0 64 64"` —
**заменить на перерисованный SVG**; второй экземпляр в футере ~строка 500), срочный баннер
(голосование до 20 июня → `/p/nachalo-golosovaniya-2026/`), 4 плитки быстрых действий
(Взносы / Электроэнергия / Документы / Контакты), ленту новостей (featured + 5 компактных строк
с реальными заголовками/датами сайта), чипы категорий без дублей, архив по годам (2026:10,
2025:43, 2024:11, 2023:12), футер с контактами, мобильную нижнюю навигацию (<640px, 4 пункта),
тёмную/светлую тему (localStorage `orbita-theme` + `prefers-color-scheme`).

## 4. Роль дизайн-агента (суб-агент)

Создай отдельного суб-агента «Дизайнер» (в Antigravity — суб-агент/планировщик с ролью
UI/UX-дизайнера) и отдай ему проверку и правки прототипа. Его задачи:

1. **Аудит прототипа** против целей: современно, понятно садоводам любого возраста
   (включая пожилых — крупный читаемый текст, очевидные кнопки), мультидевайс (320 → 1920px).
   Проверить: иерархию заголовков, размер и межстрочность текста, контраст всех пар
   фон/текст в обеих темах, состояние hover/focus/active, поведение при переносе длинных
   заголовков, пустые состояния.
2. **Перерисовать SVG-логотип** по `assets/logo-source.webp`: тёмно-синий (~#1A2440) дом
   с трубой и дымком внутри орбитальной эллиптической траектории со звездой и точкой-планетой.
   Заменить оба SVG-плейсхолдера в `orbita-redesign.html` (шапка и футер). SVG должен быть
   чистым, без встроенного растра, масштабируемым, корректным на светлом и тёмном фоне
   (если логотип с бирюзовой подложкой — сделать вариант с прозрачной подложкой для шапки,
   navy-контур на `currentColor`).
3. **Внести правки в прототип** по итогам аудита (правки — в HTML/CSS инлайн, как сейчас).
4. **Составить список правок** `CHANGES.md`: что изменено и почему (по пунктам,
   с указанием секций прототипа).

Дизайн-агент не трогает ничего вне папки задания.

## 4.1. Критерии приёмки дизайна (как понять «достаточно хорошо»)

«Идеального» дизайна не существует — есть измеримые критерии. Дизайн считается готовым,
когда выполнены ВСЕ пункты ниже. Это же чеклист — критерий остановки, чтобы не править
бесконечно.

**Автоматические проверки (агент обязан выполнить и приложить результаты):**
* Lighthouse по прототипу: Accessibility ≥ 0.98, Best Practices ≥ 1.0, SEO ≥ 1.0
  (базовый сайт: 0.94 из-за контраста — это минимум, который надо побить).
* Контраст всех пар текст/фон в обеих темах ≥ 4.5:1 (проверить программно каждый
  токен, включая ссылки, даты, чипы).
* Консоль браузера: 0 ошибок и предупреждений на desktop и mobile-виде.
* Тач-таргеты ≥ 44×44px; шапка не перекрывает контент при скролле; бургер-меню
  открывается/закрывается, Esc закрывает.
* Все 4 брейкпоинта (320/390/768/1200) в светлой и тёмной темах: скриншоты без
  горизонтального скролла, наездов текста, обрезанных кнопок.

**Эвристики UX (агент проверяет и фиксирует в CHANGES.md):**
* Правило 3 кликов: Взносы, Электроэнергия, Документы, Контакты, свежее голосование —
  каждое достижимо с главной за ≤3 кликов (прототип: 1 клик по плитке — проверить).
* Первый экран отвечает «что это и что для меня срочно»: сайт + срочный баннер +
  плитки видны без скролла на 390px.
* Меню desktop ≤ 7 пунктов, читаемые формулировки без жаргона.
* Возраст аудитории 50–80 лет: база ≥17px, межстрочный ≥1.5, никаких иконок без подписей
  в критических местах, предупреждения дублируются текстом, не только цветом.

**Человеческий тест (единственный настоящий ответ на «удобно ли») — после этапа 1:**
* 3–5 реальных членов СНТ (обязательно включая старших 60+), 3 задачи:
  «заплати взнос», «найди, как шла голосование», «найди телефон правления».
* Критерий успеха: ≥4 из 5 справляются с каждой задачей за ≤1 минуту без подсказок.
* Наблюдать, где «спотыкаются» — это и есть список финальных правок.

Когда все автоматические проверки пройдены и заказчик после человеческого теста сказал
«одобряю» — дизайн ЗАВЕРШЁН, дальнейшие правки прекращаются.

## 6. Этап 2 — внедрение в Hugo (выполняется ПОСЛЕ одобрения)

**Область:** шаблоны/стили/контент Hugo-сайта. **Деплой на NAS НЕ делать** —
только локальная сборка и коммит в ветку.

Шаги:
1. Создать ветку `redesign-2026-11`.
2. **Новая тема рядом со Stack** (не форк, не правка `themes/hugo-theme-stack/` —
   это подмодуль, правки запрещены правилами GEMINI.md):
   `themes/orbita/` — своя тема на базе структуры Stack (layouts/partials, assets/scss),
   либо переопределения в корне `layouts/` + `assets/`, если новую тему заводить избыточно.
   Способ выбрать по объёму правок и зафиксировать решение в PLAN.md.
3. Перенести дизайн из одобренного прототипа:
   `assets/scss/custom.scss` (токены из п. 3 через `@use`/переменные),
   partials шапки/футера/карточек, меню с приоритизацией (6 пунктов desktop,
   полное меню в бургере), срочный баннер, плитки быстрых действий, мобильную
   нижнюю навигацию, тёмную тему по прототипу (`data-theme` + localStorage).
4. **Чистка категорий** (front-matter в `content/post/**`): дубли слить —
   `Объявление`→`Объявления`, `Важно`→`Важное`, `Собрание`→`Собрания`,
   `Рабочая Группа`→`Рабочие Группы`. Список всех 29 текущих категорий вывести в отчёт
   и предложить финальный чистый набор (≤12) до массовой замены.
5. Заменить логотип: перерисованный SVG → `static/orlogo.svg` (или `assets/`),
   favicon `static/logo_fav.png` обновить из логотипа, `params.mainSections`/og-image
   сверить.
6. **Обратная совместимость (обязательно):** все статьи уже существуют и должны работать
   как раньше. Проверить выборку старых постов за каждый год 2023–2026: URL `/p/:slug/`,
   RSS `/index.xml`, старые шорткоды (`alert`, `figure`, `columns`), изображения в
   Page Bundle, пагинация, страницы категорий, архив по месяцам. Новая тема не должна
   ломать ни один существующий пост — при малейшей потере функциональности откатывать
   правку и чинить, а не «пожимать плечами».
7. **README для редактора — новые возможности (обязательно):** каждую новую возможность
   оформления, которую даёт редизайн, задокументировать в `README-redesign.md`
   (в этой папке) простым языком для редактора (роль `snt-editor`), с готовыми
   YAML-примерами front-matter «скопируй и вставь». Минимум: как сделать статью
   **срочным баннером** (как голосование в прототипе — баннер сверху главной со
   ссылкой на пост), как вывести статью в **featured-карточку** ленты, как управлять
   **плитками быстрых действий**, как назначить посту приоритет/срок показа. Указать
   имена параметров, значения по умолчанию и что происходит, если параметр не задан
   (сайт должен выглядеть как раньше). Новых возможностей может быть больше — агенту
   добавлять их в README по мере появления.
8. **Верификация:** `/opt/homebrew/bin/hugo --minify` без ошибок; открыть `public/`
   локально и снять Lighthouse (цель: Accessibility ≥0.98, Best Practices ≥1.0,
   SEO 100), скриншоты desktop/mobile светлая+тёмная; отчёт в `REPORT.md`.
9. Коммит и пуш ветки `redesign-2026-11` на GitHub. **Не мержить в main, не деплоить.**
